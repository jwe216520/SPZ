# 給佩珍的一封信

HTML、CSS、JavaScript 靜態網站，不需要 npm、資料庫或付費服務。

## 在 VS Code 預覽

1. 用 VS Code 開啟 `SPZ` 資料夾。
2. 安裝 Live Server 擴充套件，在 `index.html` 按右鍵 → Open with Live Server。
3. 或在此資料夾終端機執行 `python -m http.server 5500 --bind 127.0.0.1`，開啟 http://127.0.0.1:5500 。結束時按 Ctrl+C。
4. 建議使用 HTTP 預覽，讓照片與音檔的相對路徑和 GitHub Pages 發布後一致。

## 修改內容

- `content.js`：稱呼、逐幕文字、不同意回應、結尾、照片順序、本地音檔路徑。`{name}` 會自動換成 `recipient`，也能把稱呼改成「妳」。
- `styles.css`：色彩、字體、版面與動畫。
- `app.js`：翻頁、同意揭曉與音樂控制。
- `assets/`：已縮圖並移除 EXIF 的照片副本。原始照片沒有修改。

只有按「我同意」會展開照片；不同意按鈕前六次每次縮小，第七次起固定為第六次尺寸與回應，按鈕縮小到最低仍有 44 × 44 像素點擊範圍。重新整理會回到開場，不記錄或傳送回答。

## GitHub Pages 發布

文字與照片會公開可存取；noindex 只是請搜尋引擎不要索引，不是密碼保護。即使照片到結尾才顯示，檔案仍可直接存取。發布前請確認你們願意公開這些內容。

1. 在 GitHub 建立公開儲存庫，例如 `for-peizhen`（GitHub Free 的 Pages 使用公開儲存庫）。
2. 上傳 `index.html`、`styles.css`、`content.js`、`app.js`、`.nojekyll` 及整個 `assets` 資料夾。使用 GitHub 上傳時若忽略隱藏檔，純靜態檔案也可發布；用 Git 推送會保留 `.nojekyll`。
3. 若使用 VS Code 的 Git：初始化儲存庫、提交檔案、把分支改為 `main`，再 Publish to GitHub 選擇公開儲存庫。
4. 儲存庫 Settings → Pages → Source 選 Deploy from a branch → `main` → `/ (root)` → Save。
5. 等 GitHub 的部署完成，從 Pages 頁面開啟實際網址，通常為 `https://你的帳號.github.io/儲存庫名稱/`。
6. 在她會使用的手機瀏覽器，確認 MP3 能播放、故事能翻頁、三張照片都能顯示；之後修改並提交到 `main` 即會重新部署。

官方說明：https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## 現場使用與音樂限制

- 到車站途中，找一個可以停下來慢慢看的地方，預留閱讀時間。
- 先用實際手機和行動網路打開已部署網站，測試音樂。回到首頁即可重新開始。
- 預設聲音開啟，頁面載入即以未靜音狀態自動播放這首歌；瀏覽器若阻擋有聲自動播放，會顯示提示。點「打開這封信」會重試，仍沒聲音可按右上角喇叭圖示。網頁無法強制解除瀏覽器的自動播放限制。
- 使用 `assets/music.mp3`，右上角喇叭切換聲音與靜音。靜音時歌曲繼續，不會暫停或從頭播放。開信與翻頁保留你選擇的靜音狀態。
- 不設音量滑桿或音量衰減，音量交給手機實體音量鍵控制；歌曲只播放一次，結束後點喇叭重新播放。
- 載入失敗時，圖示旁會短暫提示；點喇叭重試。故事始終能閱讀。
- 音檔原檔約 10.5 MB，首次載入受行動網路速度影響。部署時務必包含整個 `assets` 資料夾。

## 驗收清單

`scripts/verify.cjs` 是可重複執行的瀏覽器驗收腳本，需要 Playwright 與 Chrome。啟動 HTTP 預覽後可執行 `node scripts/verify.cjs`；若 Playwright 不在專案的套件搜尋路徑，設定 `PLAYWRIGHT_MODULE_PATH` 為已安裝的套件路徑即可。截圖存於被 Git 忽略的 `.preview/`。音樂測試使用實際 MP3 的原生解碼與播放，另模擬首次自動播放被拒絕及檔案載入失敗。限制網路的環境可設定 `OFFLINE_PREVIEW=1`，用本地檔案回應瀏覽器 HTTP 請求，此模式仍驗證 MP3 解碼與播放，但不驗證已部署的 HTTP 伺服器與手機實體音量鍵。

- 320px 手機與桌面寬度沒有水平溢出；左滑下一頁、右滑上一頁順序正確，第一幕右滑可回到開信首頁。
- 首頁保留開信按鈕，故事頁沒有翻頁按鈕；第 1～5 頁隱藏翻頁提示但保留進度點，第 6 頁只顯示「把答案留給妳」；告白頁點右側或左滑不會略過回答；按鈕正下方直接顯示心意文字，不同意回應位於文字下方且未回答時不占空間；不同意七次以上仍停留第六句，照片不出現。
- 我同意後顯示結尾，三張字卡先顯示 `content.js` 的照片說明；第一次往下捲動後，每張字卡可見面積達一半時會自動翻成完整照片，每張只自動翻一次。仍可點擊來回翻面；手動操作過的卡片不再自動翻轉，後續捲動不覆蓋手動選擇。進入結尾的自動定位不觸發翻面。卡片各自操作，回到告白頁再進入結尾會重設為文字面。照片載入失敗仍可翻回文字。
- 點信紙右半邊下一頁、左半邊上一頁；手機左右滑動、桌面拖曳與鍵盤左右方向鍵亦可翻頁。滑動、上下捲動及選取文字不觸發額外點擊翻頁，按鈕與字卡各自操作；Tab、Enter 可操作告白按鈕，翻頁後焦點在新標題；字卡可用 Tab、Enter、空白鍵操作，減少動態效果設定會直接切換正反面。
- 斷網、播放器失敗仍能翻頁；喇叭的啟動、靜音、取消靜音、重播與失敗重試可操作，靜音仍保持播放進度。
- 重新整理回到開場；專案子路徑下樣式、程式與照片可載入。
